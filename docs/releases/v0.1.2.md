一个**纯增量**的小版本：`ActorHandle` 新增 `state_rx()` / `progress_rx()`，把状态/进度的 `watch` 接收端直接交给调用方。
同步宿主（GUI 帧循环、GTK/iOS 主线程）终于可以"有变化就重绘"，而不必轮询，也不必为了监听去开 tokio runtime。
**从 0.1.1 升级无代码改动**，不升级也不会坏。

## Added

- **`ActorHandle::state_rx()` / `ActorHandle::progress_rx()`**
  - 返回 `watch::Receiver<A::State>` / `watch::Receiver<A::Progress>`，每次调用 clone 出一个独立接收端。
  - 在此之前只有两条路：`get_state()` / `get_progress()` 轮询（浪费、且帧率决定延迟），
    或 `state_listen_async()` / `progress_listen_async()`（回调式，内部 `tokio::spawn`，
    **要求调用线程有 tokio runtime**）。GUI 回调里两条都不顺手，现在直接拿接收端自己拉：

    ```rust
    let mut states = handle.state_rx();
    let mut progress = handle.progress_rx();

    // GUI 每帧（同步，不用 await、不需要 runtime）：
    if states.has_changed().unwrap_or(false) {
        let state = states.borrow_and_update().clone();
        // 重绘
    }
    if progress.has_changed().unwrap_or(false) {
        let pct = *progress.borrow_and_update();
        // 进度条
    }
    ```

  - 异步侧同样可用：在 `select!` 里 `select! { _ = states.changed() => ... }`，
    且不需要 tokio runtime（`changed()` 只是 `watch` 的 future）。
  - 新增回归测试 `tests/basic.rs::state_rx_and_progress_rx_pull_latest`。

## 语义（和 `alive_rx()` 一样是 `watch`，三件事要先知道）

1. **只保留最新值**：actor 连推 100 次，读者只看到最后那次，中间值被跳过。
   要一条不漏地收，用 `get_events_rx()`（`broadcast`）。
2. **clone 出来的接收端第一次 `changed()` 可能立刻返回**：它继承 handle 内部的"已读位置"，
   actor 只要在启动后更新过，第一次拿到的就是**当前值**，不是"刚刚又变了一次"。
   正确姿势：先 `borrow()` 拿初值，再等 `changed()` 拿增量。
3. **actor 结束后**：`changed()` 返回 `Err`，`borrow()` 仍能读到最后一个值 ——
   把 `Err` 当作"结束了"处理，不是故障。
